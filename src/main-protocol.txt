## ITEMX Item Events
Follow all other protocols; preserve trailer order. If a trailer must be last, place ITEMX before it.

Emit an event only for an item event settled in this response (discovered, obtained, changed, used, equipped, transferred, destroyed, appraised); never for mentions, plans, guesses, scenery or unchanged items. Multiple items are allowed: place each event right after its paragraph, never batched at the end.

Default one-line form:
[itemx: id=stable_id | name=이름 | type=분류 | emoji=🗡️ | rarity=rare | display=레어 | theme=forged | affinity=fire | possession=owned | location=inventory | count=1 | power=300-699 | required=레벨 10 | durability=80/100 | cost=1200 Gold | effects=효과::설명 ;; 효과::설명 | trivia=짧은 배경]
A full appraisal needs id, name, type, emoji, rarity, display, possession, location, count, plus every appraisal field the narrative actually supports (equipment: every stated effect). Use a fitting emoji, not a default or ❔. Never invent level, durability, price, affinity or effects. Ids use letters, digits, `_`, `-`. A newly seen item is `observed` unless ownership is established.

Existing inventory ids are authoritative; patch them, never re-appraise:
[itemx: id=healing_potion | action=consume | quantity=1 | reason=물약 사용]
[itemx: id=quest_ore | action=transfer | quantity=all | destination=guild | reason=납품]
[itemx: id=sword | action=acquire | quantity=1]
[itemx: id=sword | action=equip | slot=main_hand]
[itemx: action=swap | unequip=old_sword | equip=new_sword | slot=main_hand]
[itemx: action=transform | inputs=ore:3,coal:1 | outputs=ingot:1 | reason=제련]
[itemx: id=sword | op=merge | durability=61/100]
Actions: acquire, transfer, consume, equip, unequip, move, transform, destroy, restore, swap, set; never action and op together. transfer/consume/destroy need quantity (positive integer or `all`). `reason` changes nothing. `op=merge` changes descriptive/stat fields only, never possession, location, count or slot. `op=remove` only for legacy complete loss, `op=restore` only for legacy restoration.
Money (gold, coins) the player carries is one stack per currency, listed in WALLET: reuse its id; open a new one only for a currency absent from WALLET, as id=money_<unit>, type=재화, count = the amount in plain digits (never the amount in name or cost, never count=1 for a pouch). Earning is `acquire` with the amount (allowed on held money), paying is `consume` or `transfer` with it; money at 0 stays held. When the narrative states a balance (a status window) that differs from WALLET, sync it once: [itemx: id=money_gold | action=set | count=1520 | reason=잔액 확인]. `set` is for money only.
Before equip, check the inventory: an observed item needs an `acquire` the narrative establishes first; never re-acquire an owned item except to add money; a removed item needs a narrated restore/acquire; an occupied slot needs unequip or swap. No executable tags inside thoughts, plans, examples or hypotheticals.

Enums: rarity normal|magic|rare|unique|epic|legendary|mythical|empyrean; possession observed|owned|removed; location inventory|equipped|storage|unknown; theme arcane|forged|oriental|clockwork|synthetic|celestial|organic; affinity/affinity2 fire|ice|lightning|wind|earth|light|dark|poison|blood|void; condition blessed|cursed|corrupted|glitched|sealed.
Copy narrative numbers and named effects exactly. Only when a full appraisal clearly establishes power without a literal number may power use a range: normal 10-99, magic 100-299, rare 300-699, unique 700-1499, epic 1500-3999, legendary 4000-9999, mythical 10000-29999, empyrean 30000-99999. Effect count is a maximum, never a quota: normal 0-1, magic/rare 1-2, unique/epic 2-3, legendary+ 3. `theme` is visual culture, not material (wuxia/xianxia = oriental). Affinity only when supported, never decoration.
No HTML, CSS, SVG, Markdown fences, `<itemx>` wrappers, `[emoji 이름]` markers or HTML comments (ITEMX adds its own). Values must not contain `|` or `]`; `;;` separates effects, `::` an effect's name from its description. Before finishing, check each event is complete and settled, reuses existing ids, and leaves required trailers last.
