# ITEMX CODEX 2.4.0

2.4.0은 내부 구조를 다시 짠 버전입니다. 화면과 기능은 그대로지만 **저장 형식이 바뀌었고, 2.3 이하의 기록은 읽지 않습니다.**

## 먼저 알아둘 것

- 2.4는 새 원장(`scriptstate`의 `itemx:ledger`)에 기록합니다. 2.3 이하가 쓰던 `itemx:log`·`$__itemx2_*` 키는 읽지도 지우지도 않습니다.
  그래서 2.4로 올린 채팅에서는 인벤토리·도감이 비어 있는 상태로 시작합니다.
- 기존 기록을 이어 쓰려면 **2.3에서 백업을 만든 뒤**(설정 → 백업 · 채팅 이사) 2.4에서 불러오세요.
- 2.3으로 되돌려도 그 채팅의 2.3 기록은 그대로 남아 있습니다.
- 2.3 이하가 본문에 남긴 마커(`<!--ITEMX2…-->`, `<!--CODEX2…-->`)는 화면과 모델 요청에서 자동으로 숨깁니다.
  본문에서 아예 지우고 싶으면 설정의 **옛 마커 본문에서 제거**를 누르세요(확인을 한 번 더 묻고, 대화 글은 그대로 둡니다).

## 바뀐 점

### 저장
- 본문에는 카드 자리를 가리키는 짧은 앵커(`<!--ix:k7f2q-->`)만 남습니다. 카드마다 수 KB씩 붙던 base64 데이터가 사라졌습니다.
- 기록은 채팅마다 문서 하나(`itemx:ledger`)에 모입니다. 사건, 수동 변경, 백업 복원 기준, 기록 보존 설정, 로어북 보완, 보조 출력 결과가 여기 있습니다.
- 인벤토리는 **지금 남아 있는 메시지 순서대로** 다시 계산합니다.
  - 리롤하면 이전 응답의 사건은 빠집니다.
  - 문장을 고쳐도 카드 앵커가 남아 있으면 사건은 유지됩니다.
  - 메시지를 지우면 그 메시지의 사건도 사라집니다.
  - 수동 변경(삭제·재감정 등)은 만들 때 마지막이던 메시지 뒤에 붙어 다니고, 그 메시지가 지워지면 맨 끝에서 적용됩니다.
- 긴 채팅을 빠르게 여는 체크포인트는 하나만 두고, 맞지 않으면 버리고 처음부터 계산합니다. 지워도 잃는 정보는 없습니다.

### 응답 처리
- 모델 응답의 ITEMX 태그는 받는 즉시 앵커로 바뀌고, 응답이 확정될 때 **한 번만** 저장합니다. 스트리밍 중에는 채팅을 읽거나 쓰지 않습니다.
- 카드를 다시 그리려고 채팅 전체를 다시 저장하던 동작을 없앴습니다. 표시 훅이 기록을 직접 불러와 그립니다.
- 모델에 보내는 요청에서는 앵커·옛 마커·ITEMX 태그를 모두 뺍니다.

### 보조 출력(누락 복구)
- 실제로 모델을 호출했다가 실패한 경우만 재시도 횟수(최대 3회)에 셉니다. 그 횟수는 기록에 남아 새로고침해도 같은 메시지를 다시 과금하지 않습니다.
- 시간 초과된 요청은 응답이 올 때까지 "진행 중"으로 남겨 두 번째 유료 요청이 겹치지 않게 했습니다.
- 채팅이 도중에 바뀌면 횟수를 쓰지 않고 잠시 뒤 다시 시도합니다.

### 화면
- 서랍 클릭 처리: 클릭마다 열린 탭에서 누를 수 있는 컨트롤만, 한 번에 위치를 잽니다(전에는 최대 수십 번 순서대로 물었습니다).
- 도감에서 목록 순서가 바뀐 뒤 상세가 빈 채로 뜨던 문제를 고쳤습니다.
- 설정 확인 카드·디버그 접이·헤더는 그 부분만 다시 그립니다.
- 본문 스타일시트에서 같은 내용이 두 번 들어가던 사본을 없앴습니다(약 25만 자 → 18만 자). 변경 전후를 Chromium에서 요소 8,184개의 계산 스타일로 비교해 차이가 없음을 확인했습니다.
- 배지 위치를 바꿔도 큰 스타일시트를 다시 쓰지 않습니다.
- 메인 문서 권한이 없는 환경에서 메시지마다 80 KB 스타일을 붙이던 대체 경로를 작은 칩 표시로 바꿨습니다.

### 그 밖에
- 소스를 ES 모듈로 나누고 esbuild로 번들합니다. 번들 크기 787,787 → 523,253 바이트.
- 테스트는 가짜 RisuAI 호스트와 가짜 SafeElement DOM으로 모듈을 직접 검사합니다. 순정 RisuAI 플러그인 API v3만 사용합니다.

## 실제 브라우저에서 확인이 필요한 것

자동 테스트는 가짜 호스트에서 돌았습니다. 다음은 실제 RisuAI에서 확인해 주세요.

- 응답 직후 카드가 바로 보이는지, 새로고침·채팅 전환 뒤에도 카드가 다시 그려지는지(표시 훅이 기록을 불러오는 동안 잠깐 비어 보일 수 있습니다).
- 리롤·메시지 삭제·편집 뒤 인벤토리가 기대대로 바뀌는지.
- 응답이 끝나기 전에 페이지를 닫으면 그 응답의 사건은 저장되지 않습니다(앵커만 남고 카드는 비어 보입니다). 다시 생성하면 됩니다.
- 보조 출력 재시도·시간 초과 동작과 요금.
- 서랍의 탭·상세·설정 버튼 클릭, 배지 위치 변경.

## 라이브 확인 후 수정 (같은 2.4.0)


### 카드가 본문 머리말 위에 모여 나오던 문제

카드 위치를 정할 때 `[Status: …]` 줄을 "응답 끝의 상태 블록"으로 보고 카드를 그 위로 올렸다.
응답이 상태 줄로 **시작**하면 모든 카드가 머리말 바로 아래, 본문보다 위로 몰렸다.
이제 응답을 닫는 상태 블록만 끝 블록으로 본다. 카드는 아이템 이름이 나오는 문단 뒤에 놓인다.

### 보조 모델이 멈추지 않고 계속 호출되던 문제

세 가지가 겹쳤다.

- 사고 블록(`<Thoughts>`)이나 `인라인 코드` 안에서 태그를 **언급**만 해도 처리되지 않은 원시 태그로 보았다.
  그래서 따라잡기마다 확정 처리를 다시 돌려 채팅 전체를 다시 썼다. 이제 언급은 태그로 보지 않는다.
- 같은 응답에 출력 훅이 다시 돌면 앵커 키가 매번 달라져 본문이 바뀌었다. 키는 이제 응답과 사건으로만
  정해지고, 확정된 앵커가 본문에 그대로 있으면 같은 키를 다시 쓴다. 리롤은 여전히 새 키를 받는다.
- 보조 모델을 호출한 뒤 본문이 바뀌어 저장에 실패하면 "재시도"로만 처리하고 횟수를 세지 않았다.
  이제 모델을 호출한 시도는 성공이 아니면 모두 횟수에 들어가고 문서에 기록된다. 본문 비교도 앵커를
  뺀 서사 기준이라 앵커만 바뀐 것은 충돌이 아니다.

### 보조 누락 복구 취소

보조 모델이 도는 동안 CODEX 배지 옆 "보조 복구 중" 표시에 **취소** 버튼이 뜬다. 서랍이 열려 있을 때는
설정 탭의 보조 모델 카드에 있는 버튼이 같은 동안 **보조 복구 취소**로 바뀐다. 두 버튼 모두 작업 대기열을
거치지 않으므로, 보조 모델이 응답을 기다리는 중에도 바로 눌린다.

- 취소한 메시지는 자동 보조 복구가 다시 호출하지 않는다. 설정 탭의 **지금 검사**로 직접 돌리는 것은 된다.
- 순정 RisuAI API에는 모델 호출을 중단하는 방법이 없다. 이미 보낸 요청은 제공자가 답할 때까지 진행되고
  과금될 수 있으며, 그 답은 버린다. 그 요청이 끝나기 전에는 새 보조 호출을 시작하지 않는다.
