# ITEMX CODEX 2.5.0

2.5.0은 해적 RisuAI에서 오래된 아이템이 사라져 보이던 문제를 고친 버전입니다. 스트리밍 중 화면 부담도 함께 줄였습니다.
저장 형식이 바뀌어 2.4.x로 되돌리면 2.5에서 새로 생긴 기록은 읽지 못합니다.

## 고친 문제

해적 RisuAI는 채팅을 열 때 최근 메시지 일부(기본 12개)만 불러옵니다. 2.4는 불러오지 않은 메시지를 지워진 메시지로 보고,
그 메시지에서 얻은 아이템·스킬을 빼고 계산했습니다. 예를 들어 44개짜리 채팅에서 아이템 5개 중 1개만 보였습니다.

2.5는 카드가 붙은 응답마다 그 시점의 전체 상태를 원장에 함께 남깁니다. 채팅을 열면 불러온 범위에서 가장 최근 상태를
가져오므로, 몇 개를 불러왔든 같은 인벤토리가 나옵니다.

- 최신 응답을 리롤하거나 지우면 바로 앞 응답의 상태로 돌아갑니다.
- 오래된 메시지를 지우거나 고쳐도 아이템은 남습니다. 없애려면 인벤토리에서 직접 지우세요.
- 채팅을 복사해도 인벤토리와 카드가 그대로 따라갑니다.
- 오래된 카드는 저장 때 고정한 내용으로 그려서, 앞부분을 불러오지 않아도 보입니다.

## 기존 채팅

- 2.4 채팅의 기록은 그대로 읽습니다. 상태 기록은 다음 응답이 끝날 때(전체 채팅이 불러와져 있을 때) 자동으로 생깁니다.
  그 전까지는 2.4처럼 불러온 범위만 계산합니다. 메시지를 한 번 보내면 맞게 나옵니다.
- 메시지가 200개(Capacitor 앱 100개)를 넘는 2.4 채팅은 응답 뒤에도 일부만 남아 있으므로, 맨 위까지 한 번 스크롤한 뒤 응답을
  받아야 상태 기록이 생깁니다.
- 2.4에서 백업을 불러온 채팅은 그 백업 기준 상태를 옮기지 않습니다. 필요하면 2.4에서 백업을 다시 만들어 2.5에서 불러오세요.

## 정리한 기능

- `저장소 최적화`와 `옛 마커 본문에서 제거`를 없앴습니다. 상태 기록은 최근 8개만 남겨 자동으로 정리됩니다.
- 2.3 이하가 본문에 남긴 마커는 모델 요청에서만 뺍니다. `ITEMX 정리`를 실행하면 본문에서도 지웁니다.

## 스트리밍 부담 감소

- 응답이 들어오는 동안 카드 효과를 멈춰 둡니다. Risu가 메시지를 새로 그릴 때마다 효과가 처음부터 다시 시작되지 않습니다.
- 응답이 들어오는 동안 페이지 변화 분류와 배지·서랍 동기화를 미루고, 끝난 뒤 한 번만 합니다.
  그 사이 다른 채팅으로 옮기면 바로 동기화합니다. 응답이 1.5초 동안 오지 않으면 보류가 저절로 풀립니다.
- 스킬·조우 카드 HTML을 캐시합니다.
- 응답 처리에서 문단 비교를 한 번만 합니다(긴 응답 기준 flush 1회 약 4.3ms → 3.3ms, 로컬 측정).

## 요청 토큰 절감

매 요청에 붙는 ITEMX 규칙문을 같은 규칙 그대로 짧게 다시 썼습니다. 아이템 규칙은 약 1,150토큰에서 940토큰, 스킬·조우 규칙은 약 1,160토큰에서 960토큰으로 줄었습니다. 예를 들어 아이템 6개가 있는 채팅이라면 요청당 약 2,870토큰이 약 2,470토큰이 됩니다(o200k 기준).

## 알려진 한계

- 같은 사용자 입력에 그룹 멤버 둘이 똑같은 첫 사건을 출력하면 카드 키가 겹칠 수 있습니다(2.4와 같음).
- 다른 채팅의 응답 복구(해적 로컬 패치 recovered-output)는 2.4와 같이 현재 채팅 기준으로 처리됩니다.
