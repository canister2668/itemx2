# 2.0.8 기록 화면 및 소모품 보관 검토

## 범위

- 버전 2.0.8 유지. 플러그인 소스와 배포용 번들만 변경.
- 구현 단계에서는 운영 DB 수정 및 공개 배포를 하지 않았다. 이후 별도 요청에 따라 같은 2.0.8 릴리스의 설치 파일을 갱신하며, 운영 DB는 변경하지 않는다.
- 앞서 수정한 로어북 설정 버튼 레이아웃도 유지.

## 동작

- 기본 목록은 현역 항목만 표시한다. 아이템 `removed`, 스킬 `lost`, 조우 `ended/escaped/defeated/dead`는 기록 화면에서 확인한다.
- 부분 소모는 잔여 수량을 유지한다. 손상·내구도 0만으로 무기를 숨기지 않으며, 봉인 스킬도 현역 목록에 남긴다.
- 소모품 종류와 확정된 `consume` 사건이 함께 확인될 때만 자동 보관한다. 오래된 `removed` 감정은 소모품 종류와 명확한 복용·소모 완료 설명이 있는 경우만 해당한다.
- 파괴·분실·양도된 무기, 잊은 스킬, 종료된 조우는 자동 보관하지 않는다.
- 기본 자동 보관은 정상 응답까지 완료된 새 사용자 입력 10회. 기록 화면의 주기 버튼으로 OFF/5/10/20회를 선택한다.
- 자동 보관은 목록에서의 분류 변경이며 실제 원장 삭제가 아니다. 보관됨 필터에서 다시 확인하고 보존할 수 있다.
- 보존은 기록 자동 보관 제외 설정이다. 소유권·수량·능력 상태를 복원하지 않는다. 같은 ID가 재획득·복구·재교전 상태가 되면 현재 목록으로 돌아온다.
- 이 화면은 항목별 현재 종료 상태를 보여준다. 같은 ID의 모든 과거 소비를 별도 카드로 나열하는 연대기는 아니며, 과거 사건 자체는 원장에 남는다.

## 레이아웃 및 API v3

- 헤더에 `기록`과 `✕` 버튼을 각각 항상 표시한다. 각 버튼은 36px, 간격은 6px이며 닫기는 원래 우측 위치에 유지한다. 좁은 화면의 긴 헤더 문구는 말줄임하여 높이와 카드 배치를 유지한다.
- 기록 화면은 목록 영역 안에서만 전환한다. 기존 목록 DOM은 제거하지 않고 숨겨 분류·페이지·스크롤 상태를 유지한다.
- 숨긴 목록의 FX는 일시 정지한다. 선택한 기록 상세는 기존 아이템/스킬/조우 렌더러와 effects OFF 설정을 그대로 사용한다.
- 기록 목록은 페이지당 16개이며, 상세 렌더링은 선택한 한 개에만 수행한다.
- SafeDOM의 기존 단일 클릭 라우터를 사용한다. 헤더 동작을 탭보다 먼저 처리하며 기록별 document listener는 추가하지 않는다.
- 폴딩 메뉴와 메뉴 닫기용 DOM 교체를 제거했다. 기록 화면에서도 헤더의 `✕` 한 번으로 패널을 닫는다.

## 상태와 저장

- 기존 파서·상태 전이 결과를 관찰하여 종료 시점과 사건 식별자만 snapshot의 별도 `history` 메타데이터에 둔다. 실제 registry 필드는 변경하지 않는다.
- 실패한 applyEvent는 기록 시점을 만들지 않는다. 반복된 동일 종료 감정도 기한을 갱신하지 않는다.
- 재획득 후 다시 소모한 사건은 다른 주기로 계산하므로 이전 수동 보관 표식이 새 사건을 숨기지 않는다.
- 리롤·보조 검사·새로고침 횟수를 증가시키는 영구 카운터는 없다. 선택된 메시지 흐름에서 완료된 사용자 턴을 계산하므로 메시지 삭제 시 기한도 함께 되돌아간다.
- 오래된 체크포인트에 history가 없으면 전체 원장으로 보완하여 재구축한다. 새 체크포인트에는 history를 포함하고 이후 tail replay에서 이어받는다.
- `$__itemx2_history_preferences`에는 채팅별 주기·보존·수동 보관 설정만 저장한다. 현재 열림 상태는 저장하지 않는다.
- 설정 저장은 최신 채팅을 읽는 기존 직렬 작업 큐에서 수행한다. 다른 채팅으로 전환되었거나 스트리밍 중이면 쓰지 않는다.
- 채팅 정리 기능은 이 설정 키도 제거한다. 일반 보관 동작은 메시지·원장을 삭제하지 않는다.

## 모델 문맥과 성능

- 일반 메인 요청에서 오래된 소실 아이템을 제외한다. 최근 2회 입력 이내 또는 최근 대화에 이름이 다시 나온 경우에만 수량 0의 짧은 상태를 제공한다.
- 보존 여부는 모델 주입을 강제하지 않는다. 수동 재감정 및 보조 복구용 전체 상태 검증 경로는 유지한다.
- 추가 모델 호출, 타이머, 의존성 없음. 종료 관찰은 기존 replay에서 수행하며 사건 식별자 해시는 실제 종료 메타데이터를 만들 때만 계산한다.
- 보관은 저장 용량을 줄이는 기능이 아니다. 기존 사건 원장 보존과 복원 호환성을 우선한다.

## 검증

- 일반 전체 회귀: 139개 통과, 실패 0개. 별도 실행 조건이 있는 설정 브라우저 검사 1개도 따로 실행해 통과.
- `node --check dist/itemx2.plugin.js`, `git diff --check` 통과.
- 공개 배포 준비 과정에서 기존 `src/core.js`, `tests/core.test.mjs`의 정렬 경고도 Prettier로 정리했다. 해당 두 파일은 포맷만 변경했으며 전체 `format:check`를 통과한다.
- `tests/history.test.mjs`: 전량/부분 소비, 파손 무기 유지, 무기·양도품 자동 보관 제외, 리롤/스트리밍/삭제 시 기한, legacy 단약, 보존·재획득·재소모, 봉인/상실/조우, checkpoint/prefix 수정, 모델 주입, 실패한 소비, 채팅별 설정 쓰기 경계.
- `scripts/verify-history-layout.mjs`: 실제 빌드의 UI/CSS와 API v3 형태의 SafeDOM 모형으로 320/390/768px 검증. 이전 헤더 버튼 대비 기하 동일, 기록 보존 후 수량 불변, 목록 DOM·스크롤·필터 복원, iframe 스킬/조우 상세 열기 확인.
- 실제 RisuAI 서버·실제 모바일 폰에서 실행한 종단간 검증은 별도이며 위 모형 테스트와 구분한다.

## 리뷰에서 보정한 사항

1. 팝업 아래의 탭이 클릭을 가로채는 우선순위 문제 수정.
2. 캐시가 적중해도 최신 채팅을 사용하도록 하여 사건이 없는 새 대화의 경과 횟수 반영.
3. 보존을 권한·소유 상태 복원 및 영구 모델 주입과 분리.
4. 새 소모 주기와 과거 수동 보관 주기를 분리.
5. 기존 버전/격리용 런타임 표식과 어긋났던 정적 테스트를 2.0.8 기준으로 수정. 신규 기록 기능을 포함한 번들 문자열 상한은 650,000자로 유지.
